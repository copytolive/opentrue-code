# Launch gates

No capability may be marked `RUNTIME PASS` without a receipt generated by the real component/target that executed it. Repository CI may establish `REPO PASS`; it does not substitute for Mac/VPS/domain/GPU/user evidence.

## Required order

1. Public-repository policy, secret scan, dependency/image scanning and SBOM.
2. Browser persistence, Monaco, project context, ZIP/import-export, diff/checkpoint and preview.
3. Local Ollama model benchmark and real coding task.
4. Control-plane auth/RBAC, tenant isolation, approval, rate/fair-use, retry/timeout, Redis cross-replica event bus, audit and receipt.
5. Local Bridge on explicitly approved Mac folders; test/lint/build/Git receipts plus restart recovery.
6. GitHub branch -> diff -> commit -> PR -> CI repair -> merge on a real private workload.
7. Dedicated `deploy-staging` worker: exact-SHA deployment, health and forced rollback receipt.
8. Dedicated `deploy-production` worker: prove production job cannot bypass owner/admin approval.
9. Domain/HTTPS validation plus proof PostgreSQL/Redis/Ollama/internal worker ports are private.
10. Vast/GPU worker registration, local/open-weight inference benchmark, model fallback and kill-worker lease-recovery drill.
11. Observability/alerts, billing lifecycle, security red-team, 100/500/1,000-user staging load and replacement-host restore.
12. Private-project dogfood, small public beta, then GA decision.

## Launch blocker rule

`NEEDS TARGET EVIDENCE` is correct until the real target is connected. A UI button, Docker service, workflow file or successful syntax check is never evidence that a VPS/GPU/payment/domain/user flow worked.

Any reproducible P0/P1 from `docs/THREAT_MODEL.md` blocks GA.

## Evidence to retain

Keep job ID, worker ID/target, exact commit SHA, exit code, duration, output hash, model/benchmark metrics when applicable, deployment previous/new revision, health result, rollback revision, load-test summary, backup/restore timestamps and measured RPO/RTO. Secrets must never appear in receipts, audit logs, artifacts or the public repository.

`docs/GA_STATUS.md` is the 22-gate status ledger and `docs/ACCEPTANCE_TEST.md` defines the complete acceptance evidence.
